# 04 CW decoder and audio

> This page covers how the node turns the radio's audio into text. The sound card's samples are captured by one backend per operating system: ALSA's `arecord` on Linux, Core Audio on macOS and WASAPI on Windows. They are converted to mono at the decoder's rate (8000 Hz by default) and cut into 50 ms blocks. Each block goes to the node loop's Morse decoder and, when the radio is driven through the keyer box, also to the sidetone monitor. The decoder (`crates/cw`) is a streaming, single-tone detector. It mixes the CW pitch down to 0 Hz and filters it narrowly. It decides key-down and key-up against a learned noise floor with hysteresis, learns the sender's speed by clustering mark lengths, and emits letters word by word. It builds without the standard library and without a heap, so the same code also runs on the Pico 2 decoder box (PR #30, open; built in CI and audit-cleared; no record yet of it running on hardware). The crate also holds the Morse table, the timing helpers hfnode's station layer uses for every rig, and a test-signal synthesizer that all decoder and node tests feed on. Audio capture lives in `crates/hfnode/src/audio.rs` and `audio/`. **The decoder has only been tested with synthesized audio.** No recording of a real radio is in the repository, and the bench files record no decode of an off-air signal yet.

Words used on this page, in plain terms (the [17 Glossary](17-glossary.md) has more):

| Term | Meaning here |
|---|---|
| CW, Morse | On-off keying of a carrier. In the receiver's audio it is a tone that is on (key down) or off (key up). |
| Mark, space | A key-down stretch (tone heard) and a key-up stretch (silence) in the received audio. |
| Dit, dah, unit | The short and long elements of Morse. A dit is 1 unit long and a dah 3 units. The unit is the time base everything else is measured in (see [Morse timing](#morse-timing)). |
| Element gap, character gap, word gap | The silences inside a character (1 unit), between characters (3 units) and between words (7 units). |
| WPM | Words per minute: the sending speed. One unit lasts 1200 / WPM milliseconds. |
| Pitch | The audio frequency of the received CW tone, set on the radio (the IC-7300's "CW pitch"). The node assumes 600 Hz unless `audio.pitch_hz` says otherwise. |
| Sidetone | The tone a radio plays in its own audio while it is keyed. The keyer box's host code listens for it to confirm the radio's key ([09 Keyer box: host side](09-keyer-host-side.md)). |
| Prosign | A procedural signal keyed as one character with no character gap inside, for example KN (`-.--.`) or AR (`.-.-.`). |
| SSB | Single sideband, the usual voice mode on HF. Its receiver audio is a few kHz wide, so the noise in it is conventionally measured in 2500 Hz (next row). |
| SNR in 2500 Hz | Signal-to-noise ratio with the noise measured in a 2500 Hz bandwidth, the usual convention for an SSB receiver's audio. 0 dB means the tone's power equals the noise power in 2500 Hz. This project's tests and sweeps all use it. |
| Over | The prosign that ends a transmission (K, KN, AR or SK). The node treats it as "your turn" ([`crates/protocol/src/lib.rs:131-133`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/protocol/src/lib.rs#L131-L133)). |
| CI-V | ICOM's serial control protocol. Its command `17` hands the IC-7300 text for the radio's own keyer to send ([07](07-civ-ic7300.md)). |
| Read-back | Before acting on a request, the node keys the decoded request back to the field operator, who confirms it with a second code ([03](03-field-protocol-auth-session.md)). |
| Listening window | A scheduled period when the node listens. By default it listens all the time ([`crates/hfnode/src/config.rs:209-211`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/config.rs#L209-L211), [05](05-node-loop-station-safety.md)). "Window start" is when one opens, including the first one when the node starts. |
| Goertzel | A cheap way to measure the power at one frequency over a block of samples: a two-term recursion per sample and one formula at the end ([A18](#a18-goertzel-level-measurement-pr-30)). |
| Nyquist frequency | Half the sample rate: the highest frequency a sampled signal can hold. Anything above it folds back ("aliases") onto lower frequencies. |
| Kaiser window | A taper applied to a filter's taps; its `beta` trades how sharp the filter's edge is against how much it rejects outside the pass band. |
| RP2350, ADC | The Raspberry Pi Pico 2's microcontroller, and its analog-to-digital converter, which samples audio on the Pico 2 boxes. |
| dBFS | Decibels relative to full scale. A sample of 1.0 is full scale. |
| Baseband, I and Q | Multiplying the audio by a cosine and a sine at the pitch moves the tone to 0 Hz. The two products are called I and Q, and the tone's amplitude is the length of the vector (I, Q). |
| Squelch | Here, the decoder's threshold that keeps band noise from counting as a tone. It is not the radio's squelch. |
| ALSA, `arecord`, `plughw` | The Linux sound system, its command-line recorder, and its device type that converts to any rate and channel count the caller asks for. |
| Core Audio, WASAPI, cpal | The macOS and Windows audio APIs, and the Rust crate hfnode uses to reach both. |
| USB audio codec | The sound card built into the IC-7300, reached over its USB cable. It names itself "USB Audio CODEC". |

## How it works

### Morse timing

Morse code is built from one time unit. A dit is 1 unit of tone and a dah is 3. Inside a character the elements are 1 unit apart. Characters are 3 units apart and words 7. Speed is given in words per minute, using the word PARIS as the standard word. PARIS is 43 units from its first dit to its last, and 50 with the word gap that follows it ([`crates/cw/src/morse.rs:140-146`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/morse.rs#L140-L146), [`crates/cw/src/synth.rs:162-168`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/synth.rs#L162-L168)). At W words per minute there are 50 W units in a minute, so one unit lasts 60 000 / (50 W) = **1200 / W milliseconds**: 80 ms at 15 WPM, 60 ms at 20 WPM. The code uses this formula everywhere: [`crates/cw/src/morse.rs:132-134`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/morse.rs#L132-L134), [`crates/cw/src/synth.rs:40-42`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/synth.rs#L40-L42), [`crates/cw/src/decoder.rs:242`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L242), [`crates/cw/src/decoder.rs:327-329`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L327-L329).

![The word OK keyed on a time axis in units: O is three dahs and K is dah dit dah. Elements are 1 unit apart, the letters 3 units, and the next word starts after 7 units. Below: one unit is 1200 divided by the words per minute, with values at 5, 15, 20 and 35 WPM, and the thresholds the decoder uses](diagrams/04-morse-timing.svg)

*Figure 1: Morse timing. The decoder cuts halfway between the ideal lengths: below 2 units is a dit, and a space of 2 units or more ends a character. A space of 5 units ends a word (up to 6.5 if the sender stretches letter gaps).*

Hand-sent Morse drifts from these ratios. Elements vary in length, and many operators stretch the gaps between characters and words. The decoder therefore learns the unit from what it hears, within 5 to 35 WPM, rather than being told the speed. It also learns how long this sender's character gaps are and moves its word-gap threshold to match ([Algorithm 9](#a9-word-and-character-gaps), [Algorithm 10](#a10-speed-estimation)).

### The receive chain

![Audio from the radio to the decoder on each operating system: the radio's audio goes into a sound card; on Linux arecord delivers mono 16-bit samples at the decoder's rate, on macOS and Windows cpal reads the device in its own format and hfnode averages it to mono and resamples it; all three feed the Blocker, which cuts 50 ms blocks, shows each one to the tap (the keyer's sidetone monitor) and queues it for the node loop and its decoder](diagrams/04-audio-capture.svg)

*Figure 2: the receive chain. Only macOS and Windows go through hfnode's resampler; on Linux, ALSA's `plughw` device converts. The tap sees every block before the queue, so the sidetone monitor keeps hearing the radio while the node loop is busy keying. With `[keyer] output = "ptt"` the same monitor listens for the receive noise going quiet instead of a sidetone (step 7).*

1. **The radio's audio reaches a sound card.** For the IC-7300 this is the radio's own USB audio codec on the USB cable. For any other radio on the keyer box it is the radio's headphone or speaker jack wired into a USB sound card or the computer's line input ([docs/keyer.md](../keyer.md)). For a handheld, an audio cable carries only its receive audio, from its speaker output to a sound card input ([docs/handheld.md](../handheld.md), [10 Quansheng UV-K1 handheld](10-uv-k1-handheld.md)). On the IC-7300 the audio chain depends on these menu settings: ACC/USB Output Select = AF (not the 12 kHz IF), ACC/USB AF SQL = OFF (OPEN) so squelch never gates the audio, ACC/USB AF Beep/Speech output OFF, the ACC/USB AF output level set so the strongest signals do not clip (`hfnode record` warns at a 99% peak), and CW PITCH equal to `audio.pitch_hz`. The menu table is in [docs/raspberry-pi-setup.md](../raspberry-pi-setup.md) §6 (device names in §5); the operating-system side is in [docs/macos-setup.md](../macos-setup.md) §4 and §7 (microphone permission; a launch agent may never get it and then hears silence) and [docs/windows-setup.md](../windows-setup.md) §4 (privacy settings); the level check is step 2 of [docs/hardware-test-plan.md](../hardware-test-plan.md). Radio menus in general: [07](07-civ-ic7300.md).
2. **One backend per operating system captures it**, chosen at compile time ([`crates/hfnode/src/audio.rs:21-26`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L21-L26)). Linux and other Unix systems run `arecord`; macOS and Windows use cpal. The backends are described in [Algorithm 14](#a14-linux-backend-arecord) and [Algorithm 15](#a15-macos-and-windows-backend-cpal).
3. **The audio becomes mono at `audio.sample_rate`.** `arecord` is asked for mono at the decoder's rate and ALSA converts. On macOS and Windows the device is opened in its own format (typically 44.1 or 48 kHz stereo) so that hfnode never changes the sound card's settings for other programs. hfnode averages the channels and resamples ([`crates/hfnode/src/audio.rs:10-13`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L10-L13), [Algorithm 16](#a16-resampler)).
4. **`Blocker` cuts 50 ms blocks** (`sample_rate / 20` samples) and stamps each with `Instant::now()` when it is complete. It shows each block to an optional tap, then queues it. It also warns once if the first 3 s are exact zeros. `Blocker::push` runs on the backend's thread, called "the capture thread" on this page: on Linux the thread that reads `arecord`'s pipe; on macOS and Windows cpal's data callback, on the audio thread cpal or the operating system runs, not hfnode's thread named `audio capture` ([`crates/hfnode/src/audio.rs:283-349`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L283-L349), [`crates/hfnode/src/audio/native.rs:186-209`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L186-L209), [`crates/hfnode/src/audio/native.rs:222-225`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L222-L225)).
5. **The queue never makes the capture thread wait.** It holds 200 blocks (10 s), and when it is full the oldest block is dropped ([`crates/hfnode/src/audio.rs:35-36`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L35-L36), [`crates/hfnode/src/audio.rs:65-98`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L65-L98)). A blocked capture thread would stall `arecord`, and its pipe would then deliver stale audio long after it was captured.
6. **The node loop takes blocks** with `recv_timeout(5 s)`. It drops blocks captured while the node was transmitting or tuning, plus 250 ms after, and feeds the rest to `Decoder::push` ([`crates/hfnode/src/node.rs:384-412`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L384-L412), [`crates/hfnode/src/node.rs:586-596`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L586-L596), [`crates/hfnode/src/node.rs:681`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L681)). The loop itself is [05 Node loop and station safety](05-node-loop-station-safety.md).
7. **With `station.rig = "keyer"`, a tap also feeds the sidetone monitor**, on the capture thread, before the block is queued ([`crates/hfnode/src/keyer/bench.rs:73-83`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/keyer/bench.rs#L73-L83)). The monitor measures every 10 ms of audio at the sidetone pitch. That is how the host confirms that the radio keyed and that it unkeyed (key open), because the keyer box cannot read anything back from the radio ([09 Keyer box: host side](09-keyer-host-side.md)). With `[keyer] output = "ptt"` (an FM handheld keyed by its push-to-talk line) the same tap feeds the monitor in mute mode: it confirms the radio keyed because its receive noise goes quiet ([`crates/hfnode/src/keyer/bench.rs:41-52`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/keyer/bench.rs#L41-L52), [`crates/hfnode/src/keyer/monitor.rs:156-165`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/keyer/monitor.rs#L156-L165)).

### Inside the decoder

![The decoder's processing chain: per sample, sanitize, mix to baseband and low-pass three times; once per millisecond tick, magnitude, envelope smoothing, settling, the key decision with hysteresis and squelch, level tracking, debounce into runs, the noise-texture and stale-level checks that relearn the levels, and the word-gap check; per word, speed learning by 2-means and classification into dits, dahs and characters](diagrams/04-decoder-pipeline.svg)

*Figure 3: the decoder as `decoder.rs` runs it, with each stage's constants and state. The tag at the right of each box (A1 to A11) names its section under [Algorithms and processing](#algorithms-and-processing). Letters come out only when a word ends.*

The decoder runs on every sample and makes its decisions once per "tick" of `sample_rate / 1000` samples, which is 1 ms at 8000 Hz ([`crates/cw/src/decoder.rs:249`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L249), [`crates/cw/src/decoder.rs:375-380`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L375-L380)). All lengths inside the decoder are counted in ticks and treated as milliseconds. The stages, in order, are:

1. **Mix and filter** ([Algorithm 1](#a1-mixer-and-filter)). The audio is multiplied by a cosine and a sine at the pitch, so the tone lands at 0 Hz. Then I and Q each go through three one-pole low-pass filters with a cut-off of `bandwidth_hz / 2`. Noise outside this narrow band never reaches the detector, and that is where the weak-signal gain comes from.
2. **Detect** ([Algorithm 2](#a2-detector-and-envelope)). Once per tick the decoder takes the magnitude `2 sqrt(I^2 + Q^2)`, which equals the tone's amplitude. It smooths that into an envelope over about a tenth of a dit.
3. **Decide key-down or key-up** ([Algorithm 4](#a4-key-decision)). The envelope is compared with a noise floor and a signal peak that the decoder tracks itself ([Algorithm 5](#a5-level-tracking)). There is hysteresis between the two thresholds and a squelch at 4 noise deviations above the floor.
4. **Debounce** ([Algorithm 6](#a6-debounce)). A flip that lasts less than about 0.3 dit is absorbed into the run it interrupted. The surviving runs go into a buffer for the current word as (is_mark, milliseconds) pairs.
5. **Guard against a stale floor** ([Algorithm 7](#a7-noise-held-marks-texture), [Algorithm 8](#a8-stale-levels)). The floor is frozen while the key is down. A sudden rise in band noise, or a steady carrier, could therefore hold the key down for good. Two checks catch this and relearn the levels from scratch: a mark whose envelope fluctuates like noise, and a key that has not been up for a real gap in longer than any character lasts.
6. **End the word** ([Algorithm 9](#a9-word-and-character-gaps)). A space at least as long as the word-gap threshold ends the word: 5 dits, or up to 6.5 for a sender who stretches letter gaps.
7. **Learn the speed** ([Algorithm 10](#a10-speed-estimation)). The word's marks join a history of the last 24 marks, which is split into dits and dahs by 2-means clustering on log length; this gives the dit length. Words of one or two marks, which is what isolated noise bursts make, do not train it.
8. **Classify and output** ([Algorithm 11](#a11-classification-and-output)). Each mark becomes `.` or `-` against 2 dits, each space of 2 dits or more ends a character, and each pattern is looked up in the table. The decoder emits `Char`, `Unknown` or `WordGap` events.

The decoder emits nothing until a word ends. A caller that needs the last word without waiting for its word gap calls `flush`.

### Where it runs: `std` and `no_std`

The `std` feature is on by default ([`crates/cw/Cargo.toml:8-13`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/Cargo.toml#L8-L13)). ## Algorithms and processing

The numbers in the worked examples below are for the defaults: 8000 Hz, 600 Hz pitch, 150 Hz bandwidth, 5 to 35 WPM, squelch 4, starting speed 15 WPM. Values marked "derived" were computed for this page from the code's formulas. The code does not state them.

### A1 Mixer and filter

Per sample ([`crates/cw/src/decoder.rs:356-374`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L356-L374)):

1. Sanitize: a non-finite sample becomes 0 and any other is clamped to plus or minus 4.0, keeping the time base ([`crates/cw/src/decoder.rs:357-364`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L357-L364)). One NaN or one sample whose square overflows would otherwise poison every filter and level for good. Tests feed NaN, infinity, `3e38`, `f32::MAX` and `f32::MIN` ([`crates/cw/src/decoder.rs:1183-1207`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1183-L1207)).
2. Advance the phase by `phase_step = 2 pi pitch_hz / sample_rate` and wrap it into `[0, 2 pi)` with `rem_euclid`, so it never grows until `f32` loses its fraction ([`crates/cw/src/decoder.rs:245`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L245), [`crates/cw/src/decoder.rs:365`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L365), test [`crates/cw/src/decoder.rs:1209-1217`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1209-L1217)).
3. Mix: `i = x cos(phase)`, `q = -x sin(phase)`.
4. Low-pass I and Q each through three cascaded one-pole filters, `y += alpha (x - y)`, with `alpha = 1 - exp(-2 pi fc / sample_rate)` and `fc = bandwidth_hz / 2` ([`crates/cw/src/decoder.rs:241`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L241), [`crates/cw/src/decoder.rs:246`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L246), [`crates/cw/src/decoder.rs:369-374`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L369-L374)).

At the defaults, `alpha` is about 0.057 and each stage cuts off at 75 Hz. The three stages together are 3 dB down at about 75 x sqrt(2^(1/3) - 1), roughly 38 Hz either side of the pitch (derived, using the analog approximation). Tests show a station 40 Hz off the pitch decoding exactly, and one at 1500 Hz decoding nothing ([`crates/cw/src/decoder.rs:1041-1046`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1041-L1046), [`crates/cw/src/decoder.rs:1393-1398`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1393-L1398)).

### A2 Detector and envelope

Every `samples_per_tick = max(sample_rate / 1000, 1)` samples, the decoder takes `mag = 2 sqrt(i^2 + q^2)` from the last filtered sample and runs one tick ([`crates/cw/src/decoder.rs:375-380`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L375-L380)). Mixing halves a tone's amplitude, so `mag` is the tone's amplitude in full-scale units. The default `min_level` of `1e-3` is therefore a tone at -60 dBFS.

Each tick starts by smoothing `mag` into the envelope: `env += (mag - env) / tau`, with `tau = clamp(0.12 dit_ms, 2, 12)` ticks ([`crates/cw/src/decoder.rs:398-402`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L398-L402)). At 15 WPM `tau` is 9.6 ms. The rest of the tick works on `env`, except the texture check, which uses the raw `mag`.

### A3 Settling and relearning

`ticks_seen` counts ticks since the decoder started, since `reset_levels` (which the node calls after every transmission, [`crates/cw/src/decoder.rs:280-304`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L280-L304)), or since it last relearned ([`crates/cw/src/decoder.rs:404-428`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L404-L428)).

- **Normal start, and after `reset_levels`.** For the first `SETTLE_TICKS` = 100 ticks it learns only the floor (`floor += 0.05 (env - floor)`) and the deviation (`dev += 0.05 (|env - floor| - dev)`). It sets `peak = floor`, and makes no key decision.
- **Relearning** (after [A7](#a7-noise-held-marks-texture) or [A8](#a8-stale-levels), while `relearn_mean` is set). A station may already be keying, so the tone must not be learned as noise. A running mean follows the envelope at 0.05 per tick. Only envelope values at or below that mean teach the floor, at 0.1 per tick, and only values between 0.5 and 2 times the floor teach the deviation, at 0.05. After 100 ticks, `relearn_mean` is cleared and that same tick goes on to a key decision.

### A4 Key decision

([`crates/cw/src/decoder.rs:430-438`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L430-L438))

```text
noise_gate = max(floor + squelch_sigmas * dev, min_level)
span       = max(peak - floor, 0)
key up   -> raw_on if env > max(floor + 0.5  * span, noise_gate)
key down -> stays  if env > max(floor + 0.35 * span, floor + 0.6 * (noise_gate - floor))
```

The thresholds sit between the noise floor and the signal peak, with hysteresis: going on takes half the span, staying on takes 0.35 of it. The squelch keeps pure noise from counting. A tone must clear the floor by 4 deviations to start, and only 60% of that to continue.

### A5 Level tracking

([`crates/cw/src/decoder.rs:440-459`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L440-L459))

| When | Update |
|---|---|
| `raw_on` (tone detected this tick) | `peak += a (env - peak)`, `a` = 0.2 if `env > peak` (fast attack), else 0.01 (slow decay). |
| Key up for more than `0.6 dit_ms` (well into a debounced gap, clear of the last element's tail) | `floor += a (env - floor)`, `a` = 0.02 if `env < floor` (falls quickly), else 0.002 (rises slowly). `dev += 0.005 (d - dev)`, where `d = min(|env - floor|, 4 dev + min_level)`: the deviation sample is clipped, so a stray tone barely moves it. Adding `min_level` lets a deviation learned on digital silence (0) still grow when band noise arrives. `peak += 0.0005 (floor - peak)`: the peak relaxes towards the floor over a few seconds, so a weaker station after a strong one is still heard. |
| Otherwise (early in a gap) | Nothing. |

### A6 Debounce

([`crates/cw/src/decoder.rs:461-483`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L461-L483))

`min_dit = 1200 / max_wpm` (34.3 ms) and `glitch = clamp(0.3 dit_ms, 0.4 min_dit, 40)`, truncated to whole ticks. At 15 WPM `glitch` is 24 ticks, at 35 WPM it is 13, and at 5 WPM it is 40 (derived).

- If `raw_on` equals the debounced state `on`, the run continues. Any candidate ticks counted against it are folded back in: `run_ticks += 1 + candidate_ticks`.
- Otherwise `candidate_ticks` counts up. When it reaches `glitch`, the state flips. The finished run, of length `run_ticks`, is pushed to the word, and the new run starts at `candidate_ticks`, so lengths are measured from the raw edge, not from the debounced one.
  - A finished mark is always pushed as `(true, len)`.
  - A finished space is pushed only if the word already has something in it, because words start with a mark. Before it is pushed, a space of at least `2 dit_ms` also updates the character-gap estimate: `char_gap_ms += 0.2 (len - char_gap_ms)`.

`push_run` adds the run to the word buffer. Without `std`, a full buffer (512 runs) first decodes the word and emits a `WordGap` ([`crates/cw/src/decoder.rs:528-543`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L528-L543)).

### A7 Noise-held marks (texture)

The floor only moves while the key is up. If band noise rises suddenly, the noise itself can hold the key down, or make it chatter, indefinitely. A tone's envelope is steady, while noise's fluctuates ([`crates/cw/src/decoder.rs:21-27`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L21-L27), [`crates/cw/src/decoder.rs:485-503`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L485-L503)):

1. While the key is down, once `run_ticks > glitch + 20`, each raw `mag` goes into a ring buffer. Values leave the ring into running sums (count, sum, sum of squares) only once more than `glitch + 20` are queued. This leaves out the filter's rise at the start of the mark, and its fall plus the debounce at the end, which are still in the ring when the mark ends.
2. Once 60 values are summed, `mark_is_noise` computes the coefficient of variation: standard deviation over mean. If it is above `NOISE_CV` = 0.4 the decoder relearns its levels ([`crates/cw/src/decoder.rs:545-551`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L545-L551)).
3. With the key up, the sums and the ring are cleared.

A long mark is first judged `2 glitch + 100` ticks after its raw start: 148 ms at 15 WPM (derived). Judging goes on through the trailing debounce, while `on` is still set after the raw key-up: `run_ticks` is unchanged there, so magnitudes keep entering the ring for `glitch - 1` more ticks ([`crates/cw/src/decoder.rs:461-503`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L461-L503)). So any mark whose raw key-down lasts at least about `glitch + 101` ticks is judged: dahs up to about 31 WPM, and dits only at about 8.5 WPM and slower (derived, and checked with a small model of the debounce and texture code). The module comment says "about 100 ms".

### A8 Stale levels

([`crates/cw/src/decoder.rs:505-515`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L505-L515), [`crates/cw/src/decoder.rs:553-560`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L553-L560))

A "real gap" is a key-up run of at least `2 min_dit` (68.6 ms). On each real gap the decoder notes `busy_word_len = word.len()` and zeroes `busy_ticks`. Every other tick adds one to `busy_ticks`. When `busy_ticks > stale_ms`, the decoder relearns its levels. `stale_ms = max(4 max_dit, 1.3 x 19 x 2 min_dit)`: either a dah at the slowest speed, or the longest character in time (`0`, 19 units, tied with `,` `)` `'`) at the speed whose element gaps are just a real gap, with 30% to spare for hand keying. At the defaults that is max(960, 1694) = 1694 ms (derived). A steady carrier, such as someone tuning up on the frequency, trips it.

**Relearning** ([`crates/cw/src/decoder.rs:562-583`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L562-L583)) truncates the word to `busy_word_len`, which drops every run since the last real gap so that the noise neither decodes nor trains the speed. If anything is left, it decodes that and emits `WordGap`. It then clears the key state and the texture, sets `floor = env`, starts `relearn_mean = env`, and zeroes `ticks_seen` so that [A3](#a3-settling-and-relearning) runs again.

### A9 Word and character gaps

Each tick with the key up sets `idle_ms = run_ticks`. If the word is not empty and `run_ticks >= word_gap_threshold()`, the decoder finishes the word and emits `WordGap` ([`crates/cw/src/decoder.rs:517-525`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L517-L525)).

`word_gap_threshold = clamp(1.6 char_gap_ms, 5 dit, 6.5 dit)`, where `dit` is the working dit ([`crates/cw/src/decoder.rs:585-590`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L585-L590)). This puts it midway between a 3-unit and a 7-unit gap, and further out for a sender who stretches character gaps (`char_gap_ms` starts at 3 dits and learns from every in-word gap of 2 dits or more, [A6](#a6-debounce)). Once the word has 3 marks, the working dit is estimated from the history plus this word's marks (cached per mark count) ([`crates/cw/src/decoder.rs:668-687`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L668-L687)). So a sender much faster or slower than the last one does not have their first word cut into pieces.

At the start, `char_gap_ms` = 240 ms and the dit is 80 ms, so the threshold is clamp(384, 400, 520) = 400 ms (derived).

### A10 Speed estimation

When a word finishes, `learn_speed` takes its marks ([`crates/cw/src/decoder.rs:592-617`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L592-L617)):

- Fewer than 3 marks: nothing is learned. Isolated noise bursts decode as E or T, and would otherwise drag the speed towards whatever length the noise happens to have.
- If the upper median of the marks is below `0.6 min_dit` (20.6 ms), the word is a burst of noise blips and nothing is learned ([`crates/cw/src/decoder.rs:735-751`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L735-L751)).
- Otherwise each mark goes into the 24-mark history, oldest out first, and the dit is re-estimated after each one.

`estimate_dit(history, more, current)` ([`crates/cw/src/decoder.rs:623-666`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L623-L666)):

1. Take `ln(max(m, 1))` of every mark.
2. **Two populations** (at least 3 marks, longest over shortest more than 1.8): run 1-D 2-means on the logs, starting from the midpoint, for at most 8 iterations or until one side is empty. The dit is `(exp(mean of short logs) + exp(mean of long logs) / 3) / 2`, the average of the dit cluster's geometric mean and a third of the dah cluster's, clamped to `[min_dit, max_dit]`.
3. **One population:** if the newest mark is shorter than twice the current dit it is a dit, otherwise a dah worth a third of its length. Move 30% of the way towards it: `0.7 current + 0.3 estimate`, clamped.
4. No marks: keep `current`.

Clustering on the log of the length treats a dit-to-dah ratio of 1:3 the same at every speed. Including the history means a word of all dits or all dahs is still classified against the speed already learned.

### A11 Classification and output

`finish_word` ([`crates/cw/src/decoder.rs:689-714`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L689-L714)) resets the working-dit cache, runs `learn_speed`, then walks the word's runs:

- A mark shorter than `2 dit_ms` is `.`, otherwise `-`.
- A space of `2 dit_ms` or more ends the character. The pattern is looked up with `decode_pattern` and emitted as `Event::Char(c)`, or as `Event::Unknown(pattern)` if it is not in the table.
- After the last run the final character is emitted and the word is cleared.

The tick that found the word gap then emits `Event::WordGap`. With `std`, `events_to_text` renders the events as text ([`crates/cw/src/decoder.rs:717-733`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L717-L733)).

### How it behaves in noise

- **Stray letters in plain noise.** With a squelch of 4 deviations, noise peaks sometimes cross the gate for longer than the debounce. Each one is a single short mark, a word of one mark, which decodes as `E` (or `T` if it is long). The unit test tolerates up to 2 letters in 20 s of noise with sigma 0.1 ([`crates/cw/src/decoder.rs:1048-1057`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1048-L1057)). The project notes' `decoder-stray-e-noise.md` records 40 to 86 stray letters per 300 s of noise alone (8 to 17 a minute) over 5 seeds (measured 2026-10-08 by the IC-7300 unattended thread; noise level not recorded there). On the air a stray E can merge into a caller's first letter (E followed by A reads as U). The node absorbs most of this in three ways. One- and two-character words of E, T, I, A, N or M do not hold a message open after an over ([`crates/hfnode/src/node.rs:419-423`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L419-L423)). Words of one or two marks (a lone E or T, or EE, ET, TE, TT) do not train the speed, and nor do bursts whose upper median mark is under 0.6 of the dit at the fastest speed, 20.6 ms ([A10](#a10-speed-estimation)); two-letter noise words of 3 or 4 marks, such as AI or MM, still do, which is why the node resets the speed ("Minutes of noise teach a wrong speed", below). And the field protocol repeats a transmission that gets no answer ([03](03-field-protocol-auth-session.md)).
- **Weak signals.** In the unit tests, 18 WPM at 0 dB and -3 dB (SNR in 2500 Hz) decodes with at most 2 character errors in 48, and a sloppy hand key at 3 dB with at most 3 ([`crates/cw/src/decoder.rs:1008-1039`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1008-L1039)). Whole exchanges in the 2026-10-04 sweep pass every trial down to -3 dB at 8 to 35 WPM, machine-keyed, and almost nothing gets through at -6 dB ([Measured performance](#measured-performance)).
- **A sudden rise in band noise** is caught by the texture check ([A7](#a7-noise-held-marks-texture)) or the stale check ([A8](#a8-stale-levels)). Tests step the noise up by 10, 15, 20 and 30 dB with a message 1 to 4 s later, and check that the message still decodes. They also cover band noise arriving after digital silence, and check that a +6 dB step does not teach a false speed ([`crates/cw/src/decoder.rs:1059-1164`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1059-L1164)).
- **A steady carrier** (3 s of tone, then the message 1 s later) is dropped by the stale check, and the message decodes exactly ([`crates/cw/src/decoder.rs:1166-1181`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1166-L1181)).
- **Minutes of noise teach a wrong speed.** Noise "words" of three or more marks train the estimate. The node therefore calls `reset_speed` at the first idle moment once 60 s of audio have passed since the window opened, it last transmitted, or the speed was last reset; audio heard in that minute does not postpone it ([`crates/hfnode/src/node.rs:675-678`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L675-L678)). A test shows the reset recovering calls that five minutes of noise had garbled ([`crates/cw/src/decoder.rs:1269-1303`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L1269-L1303)). `hfnode listen` and `hfnode decode` never reset the speed.
- **The node's own transmissions** are never decoded. The node loop drops audio captured while it transmits or tunes, plus 250 ms of samples after. After a transmission it then calls `reset_levels`; after the window-start tune it builds a fresh decoder instead ([`crates/hfnode/src/node.rs:373-412`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L373-L412), [`crates/hfnode/src/node.rs:635-636`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L635-L636), [`crates/hfnode/src/node.rs:759-764`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L759-L764)). The self-test treats a self-decode as a hard failure ([`crates/hfnode/src/selftest.rs:4050-4059`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/selftest.rs#L4050-L4059)).

### A12 Synthesizer

`Keyer::timing` ([`crates/cw/src/synth.rs:44-70`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/synth.rs#L44-L70)) produces runs. Each element is 1 or 3 units, followed by an element gap of 1 unit when it is not the last in its character. Each character is followed by `3 x gap_stretch` units when it is not the last in its word, and each word by `7 x gap_stretch` units when it is not the last. Every run is multiplied by `1 + jitter x g`, with `g` a standard normal sample, and floored at 0.2 units. The PRNG is seeded from `seed`, so the same seed gives the same timing.

`Keyer::render` ([`crates/cw/src/synth.rs:72-100`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/synth.rs#L72-L100)) writes `lead_ms` of zeros, then the runs. Gaps are zeros. A mark is `amplitude x shape x sin(w t)`, where `t` is the absolute sample index, so the tone's phase is continuous across marks. `shape` is a raised-cosine ramp over `edge_ms` (5 ms) at each end, as a real transmitter's keying shaping would make it. It ends with `lead_ms` of zeros.

`Noise::add` adds `sigma x g` to every sample. `g` comes from Box-Muller on a 64-bit xorshift* generator (multiplier `0x2545F4914F6CDD1D`), seeded with `seed x 0x9E3779B97F4A7C15 | 1` ([`crates/cw/src/synth.rs:133-156`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/synth.rs#L133-L156)).

`sigma_for_snr` ([`crates/cw/src/synth.rs:123-130`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/synth.rs#L123-L130)): the tone's power is `A^2 / 2`. The noise power wanted in `bandwidth_hz` is that over `10^(snr/10)`. White noise spreads over `sample_rate / 2`, so `sigma = sqrt(noise_in_band x (sample_rate / 2) / bandwidth_hz)`. For A = 0.5, 0 dB, 8000 Hz and 2500 Hz, sigma is about 0.45 (derived).

### A13 Capture and blocks

`Blocker::push` ([`crates/hfnode/src/audio.rs:313-348`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L313-L348)):

1. **Silence watch.** For the first `SILENCE_CHECK_SECS` = 3 s of samples it records whether any sample is non-zero. If none is, it logs one warning that names the macOS and Windows microphone privacy settings and the radio's ACC/USB AF output level ([`crates/hfnode/src/audio.rs:272-282`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L272-L282), [`crates/hfnode/src/audio.rs:315-330`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L315-L330)). A radio's audio always carries some noise, so exact zeros mean the audio is not arriving. On macOS a program without microphone permission gets silence rather than an error.
2. **Cut.** It appends to `pending` and cuts whole blocks of `max(sample_rate / 20, 1)` samples (400 at 8000 Hz). Each block is stamped `Instant::now()` when it is cut, shown to the tap if there is one, and sent to the queue. Leftover samples wait for the next call.
3. **Stop.** If `send` fails because the receiver is gone, it returns `false` and the backend stops.

The queue ([`crates/hfnode/src/audio.rs:65-157`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L65-L157)) is a `Mutex<Queue>` (the `VecDeque<Block>`, its capacity, and one flag per side) with a `Condvar` ([`crates/hfnode/src/audio.rs:45-57`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L45-L57)). Each side's `Drop` clears its flag. A full queue drops its oldest block rather than wait. Tests check the drop-oldest order, the end-of-stream handling, the wake-up, and that the tap sees every block even when the queue overflows ([`crates/hfnode/src/audio.rs:415-551`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L415-L551)).

### A14 Linux backend: arecord

([`crates/hfnode/src/audio/alsa.rs:24-55`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/alsa.rs#L24-L55))

`start` spawns `arecord -q -D <device> -f S16_LE -c 1 -t raw -r <sample_rate>` with its stdout piped. Its stderr goes to hfnode's stderr. A thread reads exactly one block (`block_len x 2` bytes) at a time with `read_exact`, converts each little-endian `i16` to `f32` by dividing by 32768, and pushes it to the `Blocker`. A read error (`arecord` exited) logs `audio capture ended` and ends the thread, which drops the queue's sender. `Source::drop` kills and reaps `arecord` ([`crates/hfnode/src/audio/alsa.rs:12-22`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/alsa.rs#L12-L22)).

`input_devices` runs `arecord -L` and `parse_list` reads its output: a name at the start of a line, then indented description lines joined with `; ` ([`crates/hfnode/src/audio/alsa.rs:57-95`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/alsa.rs#L57-L95)). ALSA's `plughw` devices convert to the rate asked for, so the Linux path never uses hfnode's resampler ([`crates/hfnode/src/audio.rs:5-9`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L5-L9)).

### A15 macOS and Windows backend: cpal

([`crates/hfnode/src/audio/native.rs:38-233`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L38-L233))

1. `start` spawns a thread named `audio capture` that opens the stream, keeps it and drops it. cpal streams cannot move between threads on every platform. This thread does not run the audio: cpal calls the data callback (step 3), and so `Blocker::push`, the tap and the sidetone monitor's lock, on its own audio thread. `start` waits on a channel for that thread to report the stream open or an error, so a bad device fails at start, not later ([`crates/hfnode/src/audio/native.rs:38-81`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L38-L81)).
2. `open` takes `cpal::default_host()`. It lists and names the input devices inside `no_panic` (`catch_unwind`), because cpal's Windows backend panics if a device vanishes while it is listed, then picks one with `pick_device`, outside it ([`crates/hfnode/src/audio/native.rs:83-102`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L83-L102)). It reads the device's `default_input_config()` and opens the stream in that format: one of `F32`, `I16`, `I32`, `I24`, `U16`, `F64`, `I8` or `U8`, with any other refused ([`crates/hfnode/src/audio/native.rs:119-174`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L119-L174)). It logs, for example, `audio: "USB Audio CODEC" at 48000 Hz, 2 channel(s), I16, converted to 8000 Hz mono`. The stream config comes from `supported.config()`, which in cpal asks for the default buffer size, and hfnode never sets one ([`crates/hfnode/src/audio/native.rs:134-137`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L134-L137)). Callback sizes are therefore whatever the operating system chooses (not measured here); the `Blocker` re-cuts them into 50 ms blocks.
3. Each callback (`Sink::take`) averages the interleaved frames to mono `f32`, resamples them with a `Resampler::new(device_rate, sample_rate)` made at open, and pushes the result to the `Blocker`. If the push returns `false`, the sink marks itself ended and signals the thread to drop the stream ([`crates/hfnode/src/audio/native.rs:176-210`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L176-L210)).
4. A stream error logs `audio capture stopped: ...` and signals the thread. Dropping the stream drops the `Blocker` and its sender, so the node sees the audio end ([`crates/hfnode/src/audio/native.rs:58-61`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L58-L61), [`crates/hfnode/src/audio/native.rs:226-229`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L226-L229)).
5. On Windows, an "Access is denied" (`0x80070005`) from the device gets a hint naming the microphone privacy setting ([`crates/hfnode/src/audio/native.rs:104-117`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L104-L117)).

cpal is held at 0.16 because 0.17 links Core Audio functions that exist only from macOS 14.2, so a build would not start on an older Mac ([`crates/hfnode/src/audio/native.rs:3-5`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L3-L5), [`crates/hfnode/Cargo.toml:38-41`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/Cargo.toml#L38-L41)).

### A16 Resampler

A windowed-sinc interpolator ([`crates/hfnode/src/audio/resample.rs:1-13`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/resample.rs#L1-L13)). Each output sample is the input low-pass filtered below the lower of the two Nyquist frequencies and evaluated at that output sample's exact time. A strong signal above the lower Nyquist frequency therefore cannot alias onto the CW pitch.

Constants ([`crates/hfnode/src/audio/resample.rs:17-24`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/resample.rs#L17-L24)): `ZERO_CROSSINGS` = 16 (filter half-width in samples of the lower rate), `PASS` = 0.9 (pass-band edge as a fraction of the lower Nyquist), `KAISER_BETA` = 8.0 (about 80 dB of stop-band rejection per the comment), and `PHASES` = 64 (table points per input sample).

`Resampler::new(from, to)` ([`crates/hfnode/src/audio/resample.rs:53-88`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/resample.rs#L53-L88)):

- `step = from / to`: input samples per output sample.
- `cutoff = 0.5 x PASS x min(to / from, 1)`, in cycles per input sample.
- `half = ceil(16 x max(step, 1))`, in input samples.
- The table has `2 half x 64 + 1` points over `t` from `-half` to `+half`. Each point is `2 cutoff x sinc(2 cutoff t) x w(t)`. The Kaiser window `w = (I0(beta sqrt(1 - r^2)) - 1) / (I0(beta) - 1)`, with `r = t / half`, is shifted to reach exactly zero at the ends so that a tap just inside or just outside the span adds nothing. `I0` is a power series, stopped at 50 terms or a relative term size of 1e-12 ([`crates/hfnode/src/audio/resample.rs:143-156`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/resample.rs#L143-L156)).
- The buffer starts with `half` zeros and `pos = half`, so history before the first sample is silence and the first output falls on the first input sample.
- `passthrough` when the two rates are equal.

For 48 000 to 8000 Hz this gives `step` = 6, `cutoff` = 0.075 cycles per input sample (3600 Hz), `half` = 96 input samples (2 ms), and a table of 12 289 points (derived).

`process` ([`crates/hfnode/src/audio/resample.rs:90-125`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/resample.rs#L90-L125)) appends the input to `buf`. While `pos + half` is still inside the buffer, it sums `x[k] h(pos - k)` over the input samples within `half` of `pos`. `h` is interpolated linearly between table points ([`crates/hfnode/src/audio/resample.rs:127-140`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/resample.rs#L127-L140)). The sum is divided by the sum of the taps used, which keeps a steady level the same at every fractional position, and `pos` advances by `step`. Then it drops the input no later output can need. Output therefore lags input by `half` input samples.

Tests ([`crates/hfnode/src/audio/resample.rs:191-289`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/resample.rs#L191-L289)) check seven things. A 600 Hz tone converted from 48, 44.1, 32, 16 and 11.025 kHz keeps its pitch within 0.5 Hz and its level within 1%. Equal rates pass through unchanged, and `mono` averages stereo frames. Tones at 7400 and 8600 Hz, which would alias onto 600 Hz, leak less than 1e-3 of their level. Upsampling keeps the tone. Uneven callback sizes give the same output as one block, within 1e-6. And CW captured at 48 kHz stereo decodes exactly after the resampler.

### A18 Goertzel level measurement (PR #30)

PR #30 only, not on main ([`crates/cw/src/level.rs:9-55`](https://github.com/robinonsay/cw-message-gateway/blob/3efaf842e1aab75354e5e19d0384a703d4d786be/crates/cw/src/level.rs#L9-L55)). `goertzel_coeff` precomputes `c = 2 cos(2 pi f / fs)` for the pitch `f`. `measure` then runs one recursion per sample `v` of the slice, keeping two state values:

```text
s0 = v + c * s1 - s2;   s2 = s1;   s1 = s0;   sum_sq += v * v
```

After the last sample, `|X|^2 = max(s1^2 + s2^2 - c * s1 * s2, 0)` is the squared magnitude of the slice's spectrum at the pitch. A sine of amplitude A at the pitch gives `|X| = A n / 2`, so `tone = 2 |X|^2 / n^2` reports `A^2 / 2`, its mean square, and `total = sum_sq / n` is the slice's mean square. The two compare directly, and `purity = tone / total`. For a slice of length 0, `n` is 0 and both come out NaN (from reading; see Known bugs). The callers use 10 ms slices (80 samples at 8000 Hz): hfnode's sidetone monitor, 10 ms at `audio.sample_rate` ([`crates/hfnode/src/keyer/monitor.rs:390`](https://github.com/robinonsay/cw-message-gateway/blob/3efaf842e1aab75354e5e19d0384a703d4d786be/crates/hfnode/src/keyer/monitor.rs#L390), [`crates/hfnode/src/keyer/monitor.rs:1148-1156`](https://github.com/robinonsay/cw-message-gateway/blob/3efaf842e1aab75354e5e19d0384a703d4d786be/crates/hfnode/src/keyer/monitor.rs#L1148-L1156)) and the decoder box's loop ([`crates/decoder-core/src/control.rs:365-372`](https://github.com/robinonsay/cw-message-gateway/blob/3efaf842e1aab75354e5e19d0384a703d4d786be/crates/decoder-core/src/control.rs#L365-L372), [`crates/decoder-core/src/lib.rs:51`](https://github.com/robinonsay/cw-message-gateway/blob/3efaf842e1aab75354e5e19d0384a703d4d786be/crates/decoder-core/src/lib.rs#L51)). How they use the levels is on [09](09-keyer-host-side.md) and [11](11-decoder-box-one-pico.md).

## Programming against it

### Decode a buffer on the host

```rust
use cw::{events_to_text, Decoder, DecoderConfig};

let mut cfg = DecoderConfig::new(8000, 600.0);
cfg.bandwidth_hz = 150.0;
cfg.validate().map_err(anyhow::Error::msg)?;   // Decoder::new does not check
let mut d = Decoder::new(cfg);
let mut events = Vec::new();
for chunk in samples.chunks(400) {             // any chunk size works
    events.extend(d.push(chunk));
}
events.extend(d.flush());                      // the last word, without waiting for its gap
println!("{} ({:.0} wpm)", events_to_text(&events), d.wpm());
```

### Decode without `std` (microcontroller)

```toml
cw = { path = "../cw", default-features = false }
```

```rust
use cw::{Decoder, DecoderConfig, Event};

let cfg = DecoderConfig::new(8000, 600.0);
if cfg.check().is_err() { /* refuse */ }
let mut d = Decoder::new(cfg);                 // about 4.7 kB: keep it in a static or a large stack
d.push_with(&block, |e| match e {
    Event::Char(c) => out_char(c),
    Event::Unknown(_pattern) => out_char('*'), // the pattern is borrowed only during the call
    Event::WordGap => out_char(' '),
});
```

Words longer than `WORD_RUNS` runs are split, as if a word gap had been heard. The decoder box's own loop is in `crates/decoder-core` (PR #30, [11](11-decoder-box-one-pico.md)).

## Changing it

**Decoder constants or algorithm** (`crates/cw/src/decoder.rs`):

- Keep the module free of the standard library outside `#[cfg(feature = "std")]`: no `Vec`, `String` or `Box`, only `List`, `Buf`, `Ring` and `Pattern`. Call floating-point functions through `math`. If you need a new function, add it to both `imp` modules in `math.rs`, as PR #30 did for `cos` and `log10`.

## Known bugs, limits and flakes

- **Only synthesized audio so far.** Every decoder and node test uses `cw::synth`. The bench files record no decode of a real off-air signal yet (the Quansheng bench's stage with `hfnode listen` is "Not started" in `bench/quansheng.md`).
- **Stray E's in noise.** The project notes record 40 to 86 per 300 s of noise alone. They are tolerated by design ([How it behaves in noise](#how-it-behaves-in-noise)). They can garble a call's first letter, and they make keyer self-test scenarios sensitive to node timing (project notes `decoder-stray-e-noise.md`; [12 Testing](12-testing.md)).
- **Letters arrive a word late.** Nothing is emitted until the word gap (5 dits of silence, up to 6.5 for a sender who stretches letter gaps) or `flush`.
- **Speed range is fixed at 5 to 35 WPM** in hfnode; the dit estimate is clamped to it. Senders outside it are classified against the clamp. hfnode does not expose `min_wpm`, `max_wpm`, `initial_wpm`, `squelch_sigmas` or `min_level`.
- **One tone at a time.** Two stations inside the passband (about plus or minus 38 Hz at 150 Hz, derived) are summed into one envelope. No test covers two signals at once.
- **The SK prosign run together** (`...-.-`) is not in the table and decodes as `*`, which `protocol::OVERS` does not list ([`crates/protocol/src/lib.rs:131-133`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/protocol/src/lib.rs#L131-L133)). Only SK sent as two letters ends a message as an over. (Noticed while writing this page; not tested.)
- **Stale doc comment.** `morse.rs` says prosigns "are written as lowercase-free bracketed text by the decoder". The decoder does no such thing: unknown patterns become `Event::Unknown` and print as `*` ([`crates/cw/src/morse.rs:3-5`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/morse.rs#L3-L5)).
- **Stale comment on `WORD_RUNS`.** It says the longest character, `0`, takes 10 runs. The six-element patterns (`?`, `,`, `.` and others) take 11 runs, and `0` is the longest only in time ([`crates/cw/src/decoder.rs:214-217`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/decoder.rs#L214-L217), [`crates/cw/src/morse.rs:43-55`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/morse.rs#L43-L55)). The 512-run cap is far above either, so only the comment is wrong.
- **Stale doc comment on `Block`.** It says a block is "stamped when it was read from the sound card" ([`crates/hfnode/src/audio.rs:38`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L38)). The stamp is taken when hfnode cuts the block ([`crates/hfnode/src/audio.rs:333-337`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio.rs#L333-L337)), so `at` lags the moment the sound card sampled the audio by the `arecord` pipe's or the driver's buffering. The node relies on the 250 ms recovery after a send, counted in samples rather than time, to cover that lag ([`crates/hfnode/src/node.rs:373-376`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L373-L376), [`crates/hfnode/src/node.rs:400-411`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L400-L411)). How large the lag is on each platform has not been measured.
- **`level::measure` of an empty slice is NaN** (PR #30; from reading, not run). With `n = 0` both `tone` and `total` divide 0 by 0 ([`crates/cw/src/level.rs:47-54`](https://github.com/robinonsay/cw-message-gateway/blob/3efaf842e1aab75354e5e19d0384a703d4d786be/crates/cw/src/level.rs#L47-L54)). Every current caller passes a non-empty slice.
- **`hfnode synth --wpm 0` can exhaust memory** (from reading, not run). `wpm` is not checked, a dit of `1200 / 0` is infinite, and `render` then tries to write an endless mark ([`crates/cw/src/synth.rs:79-96`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/cw/src/synth.rs#L79-L96), [`crates/hfnode/src/main.rs:749-760`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/main.rs#L749-L760)). `--jitter` and `--pitch` are not range-checked either.
- **On Linux a wrong `audio.device` is not caught at start.** `arecord` fails after `Capture::start` has returned `Ok`, so the error appears only when the audio ends. The node stops with `audio source ended` ([`crates/hfnode/src/node.rs:592`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/node.rs#L592)). `record` fails with `audio stopped after 0.0 s`. `listen` prints `arecord`'s message and returns success. The cpal backend reports a bad device at start.
- **The device's rate is read once.** The cpal backend sizes its resampler from the default format when the stream opens ([`crates/hfnode/src/audio/native.rs:134-143`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L134-L143)). A mid-run rate change is not detected. The cross-platform memory note lists that as an open follow-up.
- **Ticks are whole samples.** A tick is `floor(sample_rate / 1000)` samples, so at 44.1 kHz a decoder "millisecond" is 0.998 ms. This is negligible, and hfnode resamples to 8000 Hz by default.
- **`audio::mono` is unused.** It is exported, but the cpal backend averages frames itself ([`crates/hfnode/src/audio/native.rs:196-201`](https://github.com/robinonsay/cw-message-gateway/blob/44185fa9a00369c379d9d8af40ca307e3867e860/crates/hfnode/src/audio/native.rs#L196-L201)).
